# ボンディング回線スループット測定ツール

Peplink ルーター(MAX BR2 Pro / MAX Transit Pro Duo)配下のPCから、
**ボンディングした回線の最大スループットとRTT**を実測するツールです。
オプションで**回線を1本ずつ自動で切り替えて、各回線単体のポテンシャル
(最大スループット・RTT)**も測定できます。

- 多並列HTTP転送で回線を飽和させ、**1秒ピーク**と**定常平均**を算出
- RTTは**無負荷時**と**転送中(負荷時)**の両方を計測 — 差が大きいほど
  バッファブロート(混雑時の遅延悪化)が大きい回線です
- 結果はコンソールの比較表+CSV(履歴追記)+JSONに保存
- [設定管理コンソール](../peplink-console/)/[IC2ロガー](../ic2-logger/)とは独立した別アプリです

## 1. 動作要件

| 項目 | 要件 |
|---|---|
| 実行場所 | **測定対象のPeplinkルーターのLAN配下のPC**(有線接続を推奨。Wi-Fi経由はWi-Fiがボトルネックになります) |
| OS / Python | Windows / macOS / Linux、Python 3.9以上 |
| 追加パッケージ | PyYAML のみ |
| PCの性能 | 1Gbps超を測る場合は有線1GbE以上のNICを推奨 |
| --per-wan 使用時 | ルーターのRouter APIが有効で、Read-Write権限の認証情報があること |

## 2. インストールと最初の測定

```bash
cd Peplink_BondingRouterSetup/tools/bonding-speedtest
python3 -m pip install -r requirements.txt

# 動作確認(ネットワークを使わずローカルで完結)
python3 run.py --demo

# ボンディング測定(設定ファイル無しでもCloudflare相手に実行できます)
```

## 3. 測定の仕組みと結果の見方

| 項目 | 意味 |
|---|---|
| **下り/上り 平均** | 立ち上がり(先頭20%)を除いた定常区間の平均スループット。**実運用で期待できる値** |
| **下り/上り ピーク** | 0.25秒サンプルの1秒間ローリング最大。**瞬間最大値** |
| **RTT(無負荷)** | 転送していない時のTCP接続確立時間(min/avg/p95) |
| **RTT(負荷中)** | 転送で回線が埋まっている最中のRTT。無負荷との差が大きい回線は、映像伝送中に遅延が膨らみやすい(バッファブロート) |
| 使用データ量 | フェーズごとに表示。従量SIMでは要確認 |

- 複数の並列TCPコネクション(既定8本)で転送するため、ボンディング測定では
  Weighted Balance等の負荷分散でも自然に複数WANへ分散します。
- 上りは送信側での計測です(末端の未達分をわずかに含む場合があります)。

### 保存されるファイル(results/)

| ファイル | 内容 |
|---|---|
| `speedtest_summary.csv` | 1フェーズ=1行のサマリ。**実行のたびに追記**され、履歴比較に使える |
| `speedtest_<日時>.json` | その実行の詳細(RTT分布、エラー等) |
| `speedtest_<日時>_samples.csv` | `--samples` 指定時のみ。0.25秒刻みの明細(グラフ化用) |

## 4. 回線ごとの測定(--per-wan)

```bash
python3 run.py --per-wan
```

各回線単体のポテンシャルを知るために、**ルーターのWAN優先度を一時的に切り替えながら**
順番に測定します。

1. 現在の優先度構成を保存
2. 対象WANだけを優先度1に、他の有効WANは優先度2(待機)に変更(Router APIの即時反映)
3. 対象WANの接続確認 → 安定待ち → 測定
4. すべての回線で繰り返し、**終了後に必ず元の優先度へ復元**(エラー時・Ctrl+C時も復元を試みます)

**重要な注意**:

- 測定中はその回線1本に全通信が乗ります。**本番運用中には実行しないでください**
- 実行前に確認プロンプトが出ます(自動化する場合のみ `--yes`)
- `config.yaml` の `router` セクション(機器IPとRead-Write権限の認証情報)が必要です
- SpeedFusionトンネル経由で通信が出ていく構成の場合、トンネルは独自のWAN優先度を
  持つため単体測定になりません。**単体測定はインターネット直行の測定先
  (既定のCloudflare)で行ってください**
- 万一復元に失敗した場合は、元の優先度が画面に表示されます。Web管理画面の
  ダッシュボードで手動復元してください

## 5. 測定先の選び方(Cloudflare / 自社サーバー)

| 測定先 | 測れるもの | 設定 |
|---|---|---|
| **Cloudflare(既定)** | インターネット直行の回線性能。回線単体のポテンシャル測定に最適 | 設定不要 |
| **自社サーバー(同梱リフレクター)** | **SpeedFusionトンネル越しの実効性能**(実際に映像が通る経路そのもの) | 下記 |

自社サーバー(本社・データセンター側)での準備:

```bash
# 測定先にするサーバーで(ポート8123で待ち受け)
python3 run.py --serve --port 8123
```

測定側の `config.yaml`:

```yaml
targets:
  download_url: http://203.0.113.10:8123/__down?bytes={bytes}
  upload_url: http://203.0.113.10:8123/__up
  rtt_host: 203.0.113.10
  rtt_port: 8123
```

> 経路がトンネルを通るかはルーターのアウトバウンドポリシー次第です。
> 「ボンディング=トンネル経由の測定先」「単体=インターネットの測定先」のように
> configを2つ用意して使い分けるのがおすすめです(`-c` で切替)。

## 6. コマンド一覧と設定

```bash
python3 run.py                     # ボンディング測定(現在の構成のまま)
python3 run.py --per-wan           # + 回線ごとの単体測定(要 router 設定)
python3 run.py --duration 20       # 1方向あたり20秒に変更
python3 run.py --limit-mb 300      # 1方向300MBで打ち切り(従量SIM保護)
python3 run.py --no-upload         # 下りとRTTのみ
python3 run.py --samples           # 0.25秒刻みの明細CSVも保存
python3 run.py -c 現場A.yaml        # 設定ファイル指定
python3 run.py --serve             # 測定先(リフレクター)として起動
python3 run.py --demo              # ネットワーク不要の動作確認
```

設定ファイルの全項目は [config.example.yaml](config.example.yaml) のコメントを参照してください。
`config.yaml` は `.gitignore` 済みです(ルーターの認証情報はコミットされません)。

## 7. 注意事項

- **データ使用量**: 例えば100Mbpsの回線を12秒×2方向測ると約300MB消費します。
  回線ごとの測定を含めるとその回線数倍になります。従量SIMでは `--limit-mb` を
  使うか、`duration` を短くしてください。
- **測定はPCの位置から**: 測定値には LAN(PC〜ルーター間)も含まれます。
  1GbEのPCで1Gbps超のボンディングは測り切れません。
- **他の通信の影響**: 測定中に配下の他の端末が通信していると、その分低く出ます。
- ルーターのCPU負荷やSpeedFusionの暗号化(AES-256)もスループット上限に影響します。

## 8. トラブルシューティング

| 症状 | 原因と対処 |
|---|---|
| 想定より大幅に遅い | PCがWi-Fi接続 → 有線に変更。他端末の通信 → 停止。`streams` を増やす(8→16) |
| 測定値が回線契約より速い | 測定経路がLAN内で完結している(測定先URLの誤り)可能性 |
| `--per-wan` で「変更権限がありません」 | Read-Onlyの認証情報。Read-Write権限のユーザー/トークンが必要([設定管理コンソールのREADME](../peplink-console/README.md#3-機器側の準備apiを使えるようにする)参照) |
| 応答をJSONとして解析できません | Router APIが無効。機器の System > Admin Security で有効化 |
| 単独測定の切替後にスキップされる | その回線が圏外・SIM未設定等で接続できていない。ダッシュボードで状態確認 |
| 社内プロキシ環境で失敗する | 既定はプロキシ不使用(直接接続)。プロキシ必須網では正確な測定はできません |
| 上りだけ極端に速い/遅い | 送信側計測のため誤差を含みます。自社リフレクター使用時はサーバー側の回線も確認 |

## 免責

本ツールは非公式のものであり、Peplink社の提供物ではありません。
