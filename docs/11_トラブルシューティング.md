# 11. トラブルシューティング

症状別の切り分け手順です。原則として **Status タブ(事実の確認)→ 該当設定(原因の特定)** の順に進みます。

## 0. まず見る場所

| 画面 | 分かること |
|---|---|
| Dashboard | 各WANの生死・優先度・エラー表示(最初に見る) |
| Status > Event Log | フェイルオーバー、切断、ヘルスチェック失敗などの履歴と時刻 |
| Status > Client List | 配下端末の接続状況・帯域消費(帯域を食い潰している端末の特定) |
| Status > Real-Time / Usage Reports | 回線別のトラフィック実績 |
| Status > SpeedFusion | トンネルの回線別の遅延・ロス・スループット |
| System > Tools > Ping/Traceroute | **回線を指定して**疎通確認(切り分けの主武器) |

## 1. セルラーが繋がらない

```
SIM認識? ──No→ 物理確認(挿し直し・向き)、スロット設定がそのSIMを向いているか(04章)
   │Yes
電波あり?(RSRP -110dBm以上) ──No→ アンテナ接続、設置場所、バンド固定していないか(04章)
   │Yes
「Connecting」で止まる ──→ APN・認証情報(04章)。スロットA/B双方を確認
   │
「Connected」だが通信不可 ──→ ヘルスチェック失敗表示? → 対象ホスト設定(03章)
                              データ上限到達(Bandwidth Allowance Exceeded)? → 03章
```

- キャリア障害の可能性もあるため、同キャリアのスマホ等での比較が有効です。
- SIM切替直後の不通は、切替に伴う再接続時間(数十秒)の場合があります。

## 2. フェイルオーバーしない/戻らない

| 確認点 | 参照 |
|---|---|
| バックアップ回線がDashboardで「Standby」になっているか(Disabledや手動Disconnectでないか) | [02章](02_ダッシュボード.md) |
| メイン回線のHealth CheckがDisabledになっていないか(**最頻出**) | [03章](03_WAN設定.md) |
| Outbound PolicyでEnforced(逃げ先なし)を使っていないか | [07章](07_詳細設定.md) |
| 復帰しない場合: Recovery Retriesが大きすぎないか、Event Logで実際の判定履歴を確認 | [03章](03_WAN設定.md) |

## 3. 速度が出ない

1. **どの区間か特定**: System > Tools で各WAN単体のping/経路を確認 →
   Status > Real-Time で回線ごとの実効スループットを確認。
2. 1回線だけ遅い → 電波指標(RSRQ/SINR)、バンド、混雑時間帯([04章](04_セルラー設定.md))。
3. 全体で遅い → Client Listで帯域消費端末を特定 → QoS/帯域制限([07章](07_詳細設定.md))。
4. 分散が偏る → 申告帯域(Upload/Download Bandwidth)が実測とずれていないか([03章](03_WAN設定.md))。
5. SpeedFusion経由だけ遅い → WAN Smoothing/FECのオーバーヘッド、暗号化のCPU負荷、
   Latency Cutoffで回線が除外されていないか([05章](05_SpeedFusion_VPN.md))。

## 4. SpeedFusionトンネルが確立しない

[05章 7節](05_SpeedFusion_VPN.md)のチェック順(PSK/ID一致 → 対向到達性/UDP4500 →
参加WANの生死 → FW世代差)に従ってください。

## 5. 「設定したのに変わらない」

| 原因 | 対処 |
|---|---|
| **Apply Changes忘れ**(最頻出) | 画面右上の赤いボタンを確認([01章](01_機器概要とログイン.md)) |
| InControl2による上書き | IC2側の設定を確認([09章](09_システム設定.md)) |
| ルール順序(Outbound Policy/FW) | 上位のルールが先に一致していないか([07章](07_詳細設定.md)) |
| ブラウザキャッシュ | 再読み込み/別ブラウザ |

## 6. 管理画面に入れない

1. 機器のLAN IPを変更した直後 → 新IPでアクセス。不明ならDHCPで配られる端末側GWを確認。
2. VLAN/ポート設定変更後 → 管理端末が管理VLANに属しているポートに接続し直す。
3. パスワード不明 → 物理リセットボタン長押しで工場出荷化(**全設定消滅**、バックアップからの復元前提)。

## 7. 意図しない再起動・不安定

- Status > Device の Uptime とEvent Logで再起動時刻を特定。
- System > Schedule に自動再起動設定が入っていないか確認。
- 電源系(車載のシガー電源の電圧降下等)・設置環境の温度も物理要因として確認。

## 8. サポートへ問い合わせる際に添えるもの

- 機種名・シリアル番号・ファームウェアバージョン
- System > Configuration の設定バックアップ
- Status > Event Log(可能なら該当時間帯を含む範囲)
- 発生時刻・頻度・影響範囲(どの回線/どの通信か)
