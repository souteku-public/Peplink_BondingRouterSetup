# 高頻度スループット記録の調査(Web GUIダッシュボード相当のデータをCSV化する)

**目的**: CSVで得られるデータが約10秒間隔なのに対し、Web GUIのダッシュボードは
それより速く更新される。ダッシュボード相当の高頻度データを記録したい。

**調査日**: 2026-07-28 / 対象FW: 8.x系

---

## 1. Web GUI のダッシュボードについて

MAX BR2 Pro / MAX Transit Pro Duo は同一ファームウェアのため、**両機種とも同じ
Web GUIダッシュボードを持つ**。リアルタイム系の画面は3つある。

| 画面 | 内容 | 更新間隔 |
|---|---|---|
| Dashboard | WAN別の接続状態と現在スループット | 数秒間隔(体感2〜3秒)で自動更新 |
| Status > Bandwidth > Real-Time | WAN別スループットのグラフ | 秒単位で描画更新 |
| Status > SpeedFusion(グラフボタン) | トンネルのWAN別スループット・遅延・ロス率 | リアルタイム描画 |

これらはブラウザ上のJavaScriptが機器内部のエンドポイントを短周期でポーリングして
描画している(公式Router APIとは別の、**非公開の内部インターフェース**)。

一方、既知の約10秒間隔のデータは InControl2 系のレポートと整合する
(フォーラムでのスタッフ回答によると InControl2 のリアルタイム報告粒度は **8〜12秒**)。

## 2. 高頻度データを取得できる経路(調査結果)

### 経路A: SNMP(推奨)— WAN別スループットの専用OIDが存在する

Peplink専用MIB(**PEPLINK-BALANCE-MIB**)に WAN 使用量テーブルがあり、
MAXシリーズでも利用できる(要: System > SNMP で有効化、MIBはPeplinkサポートから配布)。

| オブジェクト | OID | 型 |
|---|---|---|
| wanUsageThroughputIn | 1.3.6.1.4.1.23695.1.1.3.1.2 | Counter32 |
| wanUsageThroughputOut | 1.3.6.1.4.1.23695.1.1.3.1.3 | Counter32 |
| wanUsageDataTransferred | 1.3.6.1.4.1.23695.1.1.3.1.4 | Counter64 |

- ポーリング間隔は自由に選べる(**1〜5秒**での取得が現実的。SNMPは軽量で
  ダッシュボード表示と同等以上の粒度を得られる)
- Datadog公式のSNMPプロファイルもこのテーブルを使用しており、実績のある経路
- 注意: In/Out はカウンタ型のため、**2回の取得値の差分 ÷ 経過秒 = スループット**として
  計算する(単位はMIB記載が無いため、実機で1回検証して確定させる)

### 経路B: 公式 Router API のカウンタ差分

公式APIには「WAN別のリアルタイムスループット」を直接返すエンドポイントは**無い**
(フォーラムでも同じ質問があり、回答はSNMP案内のみ)。ただし以下は使える。

| エンドポイント | 取れるもの | 用途 |
|---|---|---|
| `status.pepvpn`(tunnelOption指定) | **SpeedFusionトンネルのWAN別 送受信バイト・ロス・順序乱れ・復元数・RTT** | 差分計算でトンネル品質の高頻度記録が可能。**中継用途では最重要データ** |
| `status.client` | クライアント別の送受信レート | 端末単位の帯域監視 |
| `status.wan.connection` | 電波指標(RSRP/SINR等)・接続状態 | 品質メタデータ(数秒間隔で取得可) |

### 経路C: Web GUIが使う内部エンドポイントの直接ポーリング(非推奨・要実機調査)

ダッシュボードが叩く内部URL(`/cgi-bin/MANGA/...` 系)を同じように叩けば
GUIと完全同一のデータを同じ頻度で取れるが、**非公開仕様のためFW更新で壊れる
リスクがある**。実機のブラウザで F12 → Network → XHR を見れば具体的なURLを
特定できる(必要になった場合の手段として記録)。

## 3. 結論と推奨構成

1. **WAN別スループットの高頻度記録 → SNMP(経路A)を1〜5秒間隔でポーリング**
2. **トンネル品質(ロス・RTT・復元数)→ Router API `status.pepvpn` を数秒間隔で差分記録**
3. 電波指標(RSRP/SINR)は Router API から10秒間隔程度で併記
4. 出力は機器×時刻のCSV(1行 = 1タイムスタンプ、WAN別の in/out bps・RSRP・SINR・
   トンネルロス率などを列に持つ)

既存の設定管理コンソール(tools/peplink-console)にロガーとして組み込めば、
認証・機器設定(config.yaml)をそのまま流用できる。

## 4. 実機で確認が必要な事項(実装前の30分作業)

- [ ] `status.pepvpn` のバイトカウンタ更新粒度の確認(何秒ごとに値が動くか)
