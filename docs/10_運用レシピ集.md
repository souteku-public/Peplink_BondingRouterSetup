# 10. 運用レシピ集(シナリオ別設定例)

代表的な運用シナリオごとに、「どの画面の・どの項目を・どう設定するか」をまとめます。
各項目の詳細は該当章を参照してください。

---

## レシピ1: ライブ配信・中継(ボンディングで映像を落とさない)

**目的**: セルラー2回線(+可能なら有線/Wi-Fi WAN)を束ね、瞬断・パケロスに強い伝送路を作る。

| 手順 | 画面 | 設定 |
|---|---|---|
| 1 | Network > VPN > SpeedFusion | 対向(拠点Peplink or SpeedFusion Connect)へのプロファイル作成 |
| 2 | 同プロファイル内 WAN Priority | Cellular 1 / Cellular 2 を **Priority 1**(同時ボンディング)。従量SIMはP2でも可 |
| 3 | 同プロファイル | Traffic Distribution: **Dynamic Weighted Bonding** |
| 4 | 同プロファイル(映像用サブトンネル) | **WAN Smoothing: Medium〜High**(帯域2〜3倍消費に注意)、必要に応じFEC |
| 5 | Advanced > Outbound Policy | エンコーダーのIP → 映像用サブトンネルへ **Priority** で誘導 |
| 6 | Network > WAN(各セルラー) | Standby State: **Remain Connected** |
| 7 | Status > SpeedFusion | 本番前に回線別の遅延・ロスをグラフで確認 |

**事前チェックリスト**:
- [ ] 全SIMスロットのAPN設定済み([04章](04_セルラー設定.md))
- [ ] データ上限監視のAction確認(本番中のDisconnectは致命的 → [03章](03_WAN設定.md))
- [ ] トンネル Established / 参加WAN本数の確認
- [ ] 必要ビットレート × WAN Smoothing倍率 ≦ 束ねた実効帯域 であること

## レシピ2: 固定拠点のバックアップ回線(有線メイン+セルラー待機)

**目的**: 通常は有線WANを使い、障害時のみセルラーへ自動切替する。

| 手順 | 画面 | 設定 |
|---|---|---|
| 1 | Dashboard | WAN(有線)= **P1**、Cellular 1/2 = **P2** |
| 2 | Network > WAN(有線) | Health Check: **SmartCheck または DNS Lookup**、Interval/Retriesで検知時間を調整 |
| 3 | Network > WAN(セルラー) | Standby State: 切替速度重視なら Remain Connected、通信量節約なら Disconnect |
| 4 | Network > WAN(セルラー) | Bandwidth Allowance Monitor で月間上限を設定(バックアップ用途での使いすぎ防止) |
| 5 | System > Email Notification | WAN断・フェイルオーバー時の通知を有効化 |

**ポイント**: ヘルスチェックをDisabledにしない([03章](03_WAN設定.md))。
これを切るとフェイルオーバーが機能しません。

---

## レシピ3: キャリア冗長(同一機器で2キャリアを自動使い分け)

**目的**: モデム2基に別キャリアのSIMを入れ、エリア・障害の相互補完をする。

| 手順 | 画面 | 設定 |
|---|---|---|
| 1 | Cellular 1 / 2 それぞれ | 各SIMスロットにAPN設定(キャリアA系/キャリアB系) |
| 2 | Dashboard | 両セルラーを **P1** に置き負荷分散、または一方をP2で待機 |
| 3 | Cellular詳細 | SIM Card: Both SIMs + Preferred SIM(モデム内のSIM冗長も併用) |
| 4 | Advanced > Outbound Policy | 分散させるなら Weighted Balance、セッション維持が必要な宛先は Persistence |

**ポイント**: MAX Transit Pro Duo はモデム性能が非対称(CAT-7 / CAT-12)。
速度を求める通信が CAT-12 側(Cellular 2)に乗るよう、申告帯域を実測に合わせて設定すると
Weighted Balance の配分が適正化されます。

## レシピ4: 現場Wi-Fi提供(業務とゲストの分離)

| 手順 | 画面 | 設定 |
|---|---|---|
| 1 | Network > LAN | 業務VLANとゲストVLANを作成、**Inter-VLAN Routing無効** |
| 2 | AP > Wireless SSID | 業務SSID→業務VLAN、ゲストSSID→ゲストVLAN |
| 3 | ゲストSSID | **Guest Protect有効**、WPA2/WPA3 |
| 4 | Advanced > QoS | ゲストグループに帯域上限 |

---

## レシピ5: 2台目を同一構成でセットアップ(機器複製)

1. 設定済み機器: System > Configuration > **Download Active Configurations**
2. 新機器を同一ファームウェアバージョンへ更新([09章](09_システム設定.md))
3. System > Configuration > **Restore Configuration** で設定ファイルを投入
4. 機器固有部分を修正: LAN IP(重複回避)、SSID名、SpeedFusionのLocal ID、管理パスワード
5. SIM挿入後、各スロットのAPN・接続確認

---

## レシピ6: 遠隔管理体制の整備

| 手順 | 画面 | 設定 |
|---|---|---|
| 1 | System > InControl | InControl Management 有効化(クラウドからの一括監視・設定) |
| 2 | System > Event Log | Remote Syslog転送(社内ログ基盤へ) |
| 3 | System > SNMP | 監視システムからのポーリング許可 |
| 4 | System > Admin Security | Read-onlyユーザー作成(現場用)、API Access有効化(独自ツール用) |

**注意**: InControl2管理下ではローカル変更が上書きされる項目があります([09章](09_システム設定.md))。
「現場ではダッシュボード操作のみ、設定変更はIC2または管理チーム経由」のような運用ルールを推奨します。
