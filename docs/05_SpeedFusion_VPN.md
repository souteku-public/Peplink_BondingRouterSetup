# 05. SpeedFusion / PepVPN(ボンディング)

**Network > VPN > SpeedFusion** から設定します。
複数のWAN回線を1本の仮想トンネルに束ね、**パケット単位での回線分散・瞬時フェイルオーバー・
パケロス補償**を実現する、この機種の中核機能です。

対向は以下のいずれかです。

- 拠点側のPeplink機器(Balanceシリーズ等) — 自営でトンネルを終端する構成
- **SpeedFusion Connect(旧SpeedFusion Cloud)** — Peplinkのクラウドで終端するサービス。
  対向機器を持たずにボンディングだけ使いたい場合はこちら

## 1. プロファイル基本設定

| 項目 | 意味 | 変更すると起きること・注意点 |
|---|---|---|
| Name | プロファイル名 | 管理用の表示名。通信への影響なし |
| Remote ID / Local ID | トンネル両端の識別子 | 両端で対応が取れていないと確立しない |
| Pre-shared Key | 事前共有鍵 | 両端で完全一致が必要。不一致は「Authentication failed」 |
| Remote IP Address / Host Names | 対向のIP/FQDN | 少なくとも片側が固定IP/FQDNで到達可能であること。両側動的だと確立できない |
| Data Port | トンネルのUDPポート(既定4500) | FW配下で使う場合はこのポートの許可が必要 |
| Encryption | AES-256 / OFF | OFFにすると暗号化を省きCPU負荷が下がりスループットが上がるが、盗聴耐性を失う。閉域網内以外ではAES-256を推奨 |

## 2. トンネルに参加させるWANの選択と優先度

プロファイル内の **WAN Connection Priority** で、どのWANをトンネルに使うかを決めます。
**ダッシュボードのWAN優先度とは独立**しています。

| 設定 | 変更すると起きること |
|---|---|
| Priority 1 に複数WAN | それらが**同時に**束ねられる(ボンディング) |
| Priority 2 以下 | P1系が全滅した時だけトンネルに参加(トンネル内フェイルオーバー) |
| OFF | そのWANはトンネルに使わない |

- **注意点**: 従量課金SIMをP1に入れると常時データを消費します。
  「普段は使わず、いざという時だけ」の回線はP2に置くのが定石です。

## 3. ボンディング方式(サブトンネルのTraffic Distribution)

| 方式 | 意味 | 使いどころ |
|---|---|---|
| Bonding(既定) | 全回線にパケットを分散し帯域を合算 | 帯域重視。一般的な用途 |
| Dynamic Weighted Bonding | 回線ごとの遅延・ロス状況を見て動的に配分 | 品質のばらつきが大きいセルラー束ね(=本機の主用途)で有効。**ライブ配信用途では第一候補** |

## 4. 品質チューニング(配信・中継で最重要)

### WAN Smoothing

- 同じパケットを**複数回線に複製送信**し、最初に届いたものを採用する機能。
- **変更すると起きること**: 遅延ジッタとパケロスが劇的に減る代わりに、
  **データ使用量・必要帯域が設定レベルに応じて倍増**します。

| レベル | 帯域コストの目安 | 用途 |
|---|---|---|
| Off | 等倍 | 通常データ通信 |
| Normal | 約2倍 | 軽めの保護 |
| Medium / High | 2〜3倍超 | 重要な映像伝送 |
| Maximum | 全回線に常時複製 | 絶対に落とせない生中継。データ量に注意 |

### FEC(Forward Error Correction)

- 冗長パケットを付加し、受信側でロスしたパケットを**再送なしで復元**する機能。
- Low / High から選択。**変更すると起きること**: パケロス耐性が上がる代わりに
  10〜30%程度のオーバーヘッドが乗ります。
- **WAN Smoothingとの使い分け**: ロスは多いが遅延は許容できる → FEC、
  ジッタ・瞬断も抑えたい → WAN Smoothing。併用も可能ですが帯域コストは重畳します。

### その他の品質パラメータ

| 項目 | 意味 | 変更すると起きること |
|---|---|---|
| Latency Difference Cutoff | 最速回線との遅延差がこの値を超えた回線をボンディングから一時除外 | 極端に遅い回線が全体の足を引っ張るのを防ぐ。小さすぎるとセルラーが頻繁に除外され帯域が不安定になる |
| Latency Cutoff | 絶対遅延がこの値を超えた回線を除外 | 同上 |
| Packet Fragmentation | 大きいパケットの分割方法 | 通常は既定のまま。MTU起因の問題時のみ調整 |
| Receive Buffer | 受信側で並べ替えのために待つバッファ | 増やすと順序入れ替わりに強くなるが遅延が増える。リアルタイム性重視なら小さめ |

## 5. サブトンネル(Sub-Tunnels)

1つの対向に対して、設定の異なる複数のトンネルを並行して張れます。

- 例: 「映像用 = WAN Smoothing High のトンネル」+「一般データ用 = Smoothing Off のトンネル」
- どの通信をどのサブトンネルに流すかは、アウトバウンドポリシー([07](07_詳細設定.md))で
  宛先・送信元・プロトコル別に振り分けます。
- **変更すると起きること**: 帯域コストの高い保護を映像だけに限定でき、データ量を最適化できます。

## 6. レイヤ2ボンディング(Layer 2)

- トンネルをL2ブリッジとして張り、拠点間で同一セグメントを延伸するモード。
- **注意点**: ブロードキャストもトンネルを通るため帯域を消費します。
  必要がなければ既定のL3のままにしてください。

## 7. 確認・監視

- **Status > SpeedFusion** で、トンネルごとの回線別スループット・遅延・ロス率を
  リアルタイムグラフで確認できます。**本番前の回線テストはここを見ながら**行います。
- トンネルが確立しない場合のチェック順:
  1. 両端のPre-shared Key / Remote ID の一致
  2. 対向のIP/FQDNへの到達性(Data Port UDP 4500 の開放)
  3. 参加WANがダッシュボード上でConnectedか
  4. ファームウェア世代の差(大きく違うと確立できない場合あり)
