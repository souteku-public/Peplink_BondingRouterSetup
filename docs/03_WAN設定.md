# 03. WAN設定(共通項目)

**Network > WAN**(またはダッシュボードの各WANの「Details」)から、回線ごとの詳細設定を行います。
本章では有線WAN・Wi-Fi WAN・セルラーに**共通する項目**を扱います。
セルラー固有の項目(SIM・APN・バンド)は [04. セルラー設定](04_セルラー設定.md) を参照してください。

## 1. 基本接続設定

### Connection Method(有線WANのみ)

| 設定値 | 意味 | 変更すると起きること |
|---|---|---|
| DHCP | 上流ルーターからIPを自動取得 | 一般的な構成。上流にルーターやONUがある場合はこれ |
| Static IP | IP/GW/DNSを手動指定 | 固定IP契約の回線で使用。誤入力すると即座に疎通不能 |
| PPPoE | ISPのID/パスワードで認証接続 | フレッツ系直収時に使用。認証情報誤りは「Connecting」のまま止まる |

### Routing Mode(NAT / IP Forwarding)

- **NAT(既定)**: LAN側のプライベートIPを変換してWANに出す。通常はこのまま。
- **IP Forwarding**: 変換せずルーティング。上流で経路管理している構内接続などの特殊用途。
- **注意点**: 誤ってIP Forwardingにすると、上流に経路がない限りLANから通信できなくなります。

### Standby State(待機時の挙動)

| 設定値 | 意味 | 変更すると起きること |
|---|---|---|
| Remain Connected(ホットスタンバイ) | 待機中も接続を維持 | フェイルオーバーが**数秒**で完了。ただし待機中も微量のデータ通信が発生 |
| Disconnect(コールドスタンバイ) | 待機中は切断 | データ量は節約できるが、フェイルオーバー時に接続確立から始まるため**数十秒〜**かかる |

> 中継・配信用途で瞬断が致命的な場合は、バックアップ回線も Remain Connected を推奨。

## 2. Health Check(ヘルスチェック)— フェイルオーバーの心臓部

「回線が生きているか」を判定する仕組みです。**この設定が甘いと、
実際は死んでいる回線にトラフィックが流れ続ける/逆に健全な回線が誤って切り離される**が起きます。

### Health Check Method

| 設定値 | 意味 | 特徴・変更すると起きること |
|---|---|---|
| Disabled | 判定しない | リンクアップ=生存とみなす。**上流障害を検知できず、フェイルオーバーしなくなる**。原則使用しない |
| PING | 指定ホストへping | 汎用的。ping応答しないホストを指定すると常時Failedになるので注意 |
| DNS Lookup | 指定DNSサーバーに名前解決を要求 | **有線/Wi-Fi WANの既定値**。DNSサーバー障害と回線障害を区別できない点に注意 |
| HTTP | 指定URLへHTTPアクセス | プロキシ環境など特殊構成向け |
| SmartCheck | 複数手法の組み合わせ(セルラー用) | 誤検知が減る。**セルラーWANで選択できるのはDisabledとSmartCheckの2択**(公式マニュアル記載) |

### タイミング系パラメータ

| 項目 | 意味 | 変更すると起きること |
|---|---|---|
| Health Check Interval | チェック間隔(秒) | 短くすると障害検知が速くなるが、チェック通信が増える |
| Health Check Retries | 何回連続失敗で「死」と判定するか | 少なくすると検知は速いが、瞬断で誤ってフェイルオーバーしやすくなる |
| Recovery Retries | 何回連続成功で「復活」と判定するか | 少なくすると復帰は速いが、不安定な回線でフラッピング(行ったり来たり)しやすくなる |

> **障害検知までの時間 ≒ Interval × Retries**。
> 例: Interval 5秒 × Retries 3回 → 最悪約15秒で切替。
> 配信用途で早い切替が必要なら Interval 3〜5秒/Retries 2〜3 程度が目安。
> ただしSpeedFusionボンディングを使う場合、トンネル自体がパケット単位で回線障害を吸収するため、
> ヘルスチェックを過度に攻める必要はありません。

## 3. Bandwidth Allowance Monitor(データ量監視)

月間データ量の上限を設定し、超過時の動作を決めます。従量課金SIMで特に重要です。

| 項目 | 意味 | 変更すると起きること |
|---|---|---|
| Monthly Allowance | 月間上限(GB) | 使用量がStatus画面と通知で追跡される |
| Start Day | 集計開始日 | キャリアの締め日に合わせる |
| Action(超過時) | 切断 or 通知のみ | 「Disconnect」にすると上限到達で**その回線が自動切断**される。バックアップ回線が細い場合は全体の帯域が急減する点に注意 |

## 4. DNS Servers

- **Obtain DNS server address automatically(既定)**: 回線から自動取得。
- 手動指定すると、その回線経由の名前解決に指定サーバーが使われます。
- **注意点**: DNS Lookupヘルスチェックの対象と整合させること。
  社内DNSを指定すると、その回線単独では外部の名前解決ができなくなる場合があります。

## 5. Physical Interface Settings

| 項目 | 意味 | 変更すると起きること |
|---|---|---|
| Speed(有線WAN) | ポート速度/デュプレックスの固定 | 通常Auto。相手機器との不整合があると半二重で極端に遅くなる |
| MTU | 1パケットの最大サイズ | 既定はAuto(1440前後)。PPPoEやVPN多段で断片化が疑われる時のみ調整。誤ると「pingは通るがWebが開かない」型の症状になる |
| Reply to ICMP PING | WAN側からのpingに応答するか | 無効にすると外形監視からpingで死活監視できなくなる |

## 6. Upload / Download Bandwidth(申告帯域)

- この回線の上り/下り帯域を「申告」する項目です。**実測ではなく設定値**であり、
  アウトバウンドポリシーのWeighted Balance(重み付け分散)やQoSの計算基準になります。
- **変更すると起きること**: 実力より大きく書くとその回線に過剰にトラフィックが割り当てられ、
  輻輳・パケロスの原因になります。スピードテストの実測値の8割程度を目安に設定してください。

## 7. Wi-Fi WAN 固有の注意

- Wi-Fi WANは「他所のWi-Fi(テザリング、施設Wi-Fi等)を上流として使う」機能です。
- 接続先SSID・パスワードはWAN詳細のWi-Fi WAN設定で登録します(複数登録可、優先順位あり)。
- **注意点**: Wi-Fi WANとAP(自分が吹くWi-Fi)は同じ無線チップを共有するため、
  Wi-Fi WAN利用時はAPのチャンネルがWi-Fi WAN接続先に引きずられます([08](08_AP_WiFi設定.md)参照)。
