# 07. 詳細設定(Advanced)

**Advanced** タブ配下の項目です。「どの通信をどの回線・トンネルに流すか」
「外部からのアクセスをどう受けるか」「何を遮断・制限するか」を制御します。

## 1. Outbound Policy(アウトバウンドポリシー)— 回線の使い分けルール

LANから外に出る通信を、**条件(送信元・宛先・プロトコル/ポート)ごとに
どのWAN/SpeedFusionトンネルで運ぶか**を決めるルール表です。上から順に評価されます。

### アルゴリズム一覧

| アルゴリズム | 意味・変更すると起きること |
|---|---|
| Weighted Balance | 重み付けで複数WANに分散。重みの基準は各WANの申告帯域([03章](03_WAN設定.md)) |
| Persistence | 同一送信元(または送信元+宛先)の通信を同じWANに固定。**銀行系サイト等「IPが変わるとセッションが切れる」通信の必須対策**。既定ルールはHTTPS通信にこれが効いている |
| Enforced | 指定WANに強制。そのWANがダウンしていても**他に逃げない**(通信断になる)。課金管理や検証用 |
| Priority | 指定した優先順で使い、上位ダウン時のみ下位へ。Enforcedと違い逃げ先がある |
| Overflow | 上位WANの帯域が飽和したら溢れた分を下位へ |
| Least Used | その時点で最も空いているWANへ |
| Lowest Latency | 最も遅延の小さいWANへ |
| Fastest Response Time | 全WANに同時送信し最速応答を採用(帯域コスト増) |

### 運用のポイント

- ルールは**上から順に最初に一致したものが適用**。広い条件のルールを上に置くと
  下のルールが永久に使われない、が典型的なミス。
- **SpeedFusionトンネルへ流すのもここで指定**します。例:
  「エンコーダーのIPからの通信 → SpeedFusionトンネル(Priority)」
  「それ以外 → Weighted Balance で生回線」
- 既定ルール(Default)は Auto。変更すると全体の分散挙動が変わるため、
  個別ルールで対処し、Defaultはむやみに触らないことを推奨。
- **注意点**: ルール変更のApplyで既存セッションが張り直される場合があります。
  配信中のポリシー変更は避けてください。

## 2. Port Forwarding(ポートフォワーディング)/ 受信系

| 項目 | 意味 | 注意点 |
|---|---|---|
| Port Forwarding | WAN側に来た通信を指定LAN機器へ転送 | セルラー回線は**キャリアグレードNAT配下でグローバルIPがない場合が多く、その回線では機能しない**。固定IPオプションか、SpeedFusion経由での折返しを検討 |
| NAT Mappings | 特定LAN機器の送信元グローバルIPを固定 | 追加IPがある有線WAN向けの機能 |
| UPnP / NAT-PMP | LAN機器による自動ポート開放 | 便利だがセキュリティリスク。業務用途では無効を推奨 |

## 3. Firewall(ファイアウォール)

**Advanced > Firewall > Access Rules** で Outbound / Inbound / Internal(VLAN間)の
ルールを設定します。

| 項目 | 意味 | 変更すると起きること |
|---|---|---|
| Outbound Rules | LAN→外の通信の許可/拒否 | 既定は全許可。特定宛先・ポートの遮断に使用 |
| Inbound Rules | 外→LAN(ポート転送等で受ける通信)の許可/拒否 | 既定は全拒否ベース。ポート転送を晒す場合は送信元IP制限をここで |
| Internal Network Rules | VLAN間・セグメント間 | VLAN分離の細かい例外制御 |
| Default Rule | どのルールにも一致しない場合 | **Outbound既定をDenyに変えると、明示許可した通信以外すべて止まる**。影響が非常に大きい |

- ルールは上から順に評価。**「Any-Any-Deny を上に置いて全断」**が最も危険な誤操作です。
- 各ルールの「Event Logging」を有効にすると、マッチした通信がイベントログに記録され、
  切り分けに役立ちます(大量マッチはログを圧迫するので恒常運用では絞る)。

### Content Blocking(コンテンツブロック)

- カテゴリ別Webフィルタ、ドメイン指定ブロック。適用対象をVLAN/ユーザーグループで限定可能。
- **注意点**: 業務通信のドメインが誤ってカテゴリに含まれると原因調査が難航します。
  例外(Exempted)リストを併用してください。

## 4. QoS(通信の優先制御)

| 項目 | 意味 | 変更すると起きること |
|---|---|---|
| User Groups | 端末をManager/Staff/Guestに分類(IP/サブネット単位) | 下記2機能の適用単位になる |
| Bandwidth Control | グループごとの帯域上限 | ゲスト端末の帯域を絞って業務帯域を確保、など |
| Application Prioritization | アプリ種別ごとの優先度(High/Normal/Low) | 映像伝送・VoIPをHighにすると輻輳時に優先される。**輻輳していない時は体感差なし** |

- **注意点**: QoSは「輻輳時に効く」仕組みです。根本的な帯域不足は解決しません。
  また申告帯域([03章](03_WAN設定.md))が実態とずれていると正しく機能しません。

## 5. Misc.(その他)— 見落としやすいが重要な項目

| 項目 | 意味 | 注意点 |
|---|---|---|
| Service Passthrough | SIP/FTP/TFTP/IPsec等の特殊プロトコルのNAT通過補助 | VoIPや一部VPNクライアントの不通時にここを確認 |
| GPS Forwarding | GPS位置情報を外部サーバーへ送信 | 車載運用での位置管理に使用。送信先・プロトコル(TAIP/NMEA)を指定 |
| Remote SIM Management | SIMインジェクター(遠隔SIM)の利用 | SIMを機器に挿さず拠点集中管理する構成向け |
| Wake-on-WAN 等 | 省電力関連 | 常設運用では既定のまま |

## 6. 設定例: 配信トラフィックだけをボンディングに乗せる

1. [05章](05_SpeedFusion_VPN.md)でSpeedFusionプロファイル(サブトンネル含む)を作成
2. Outbound Policy に上から順に:
   - `Source: エンコーダーIP` → **Priority: SpeedFusionトンネル(映像用サブトンネル)**
   - `Destination: 社内システムのFQDN` → **Persistence**
   - Default: Auto(その他はWAN直接で分散)
3. Apply後、Status > SpeedFusion でエンコーダーの通信がトンネルに乗っていることを確認
